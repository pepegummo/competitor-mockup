# Competitor Compare — mock-up

ขั้นตอนเต็มอยู่ใน [`docs/mockup-steps.md`](docs/mockup-steps.md)

## ติดตั้ง (Windows / PowerShell)

```powershell
cd competitor-mockup
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

สร้าง `.env` จาก `.env.example` (`copy .env.example .env`) แล้วใส่ key:

```
LLM_API_KEY=ใส่ key ของอาจารย์
```

## ทดสอบ LLM (Step 0.3)

```powershell
python -m core.llm
```

ต้องได้คำทักทายภาษาไทย และ `{'ok': True}`

## รัน

```powershell
streamlit run app.py
```

กด "เริ่มวิเคราะห์" แล้วระบบรันเบื้องหลัง (`monitor.py --job`) หน้าเว็บไม่ค้าง แสดงความคืบหน้าทุก 2 วินาที
ระหว่างรอดูผลเดิมได้ เสร็จแล้วเปิดผลให้เอง (โหมดหาคู่แข่งยังรันในหน้าเว็บ เพราะต้องให้ติ๊กยืนยันรายชื่อ)

**โหมดเดโม (สำหรับนำเสนอ):** ดับเบิลคลิก `run_demo.bat` เปิดชุดข้อมูล MC vs AP, KCE, ฟู้ดแพชชั่น ที่เก็บไว้ใน `demo/`
ใช้ได้แม้ไม่มีเน็ตหรือเครื่อง LLM ล่ม: ผลวิเคราะห์ ตัวเลข SET ทั้งหมวด ราคาหุ้น และคำตอบของคำถามตัวอย่าง (ปุ่มในแท็บถามข้อมูล
+ "AP มีโครงการใหม่อะไรบ้าง", "Shopee ลดราคาเมื่อไหร่", "บาร์บีคิวพลาซ่ามีโปรอะไรล่าสุด") ถูกเก็บไว้แล้ว
- ทุกครั้งที่เรียก LLM ระบบบันทึก prompt และคำตอบในตาราง `llm_log` · `LLM_REPLAY=1` = คำถามที่เคยถามแล้วใช้คำตอบเดิม
  ไม่เรียกเครื่อง LLM · ถ้าเครื่อง LLM ล่ม ระบบลองใช้คำตอบเดิมของ prompt เดียวกันก่อนแจ้ง error
- คำถามใหม่ที่ไม่เคยถาม และการกดวิเคราะห์ใหม่ ยังต้องใช้เน็ต

เลือกโหมดที่แถบด้านซ้าย:

| โหมด | กรอก | ได้ผล |
|---|---|---|
| เทียบคู่แข่ง (Phase 1) | คู่แข่ง 2–5 ราย | ตาราง กราฟ และรายงานกลาง ๆ |
| เรา vs คู่แข่ง (Phase 2) | บริษัทเรา + คู่แข่ง 2–5 ราย | เพิ่มแท็บ gap (เรา − ค่าเฉลี่ยคู่แข่ง) และรายงานพร้อมข้อเสนอแนะ |
| หาคู่แข่งให้ (Phase 3) | บริษัทเรา + จำนวนคู่แข่ง (3–10) + อุตสาหกรรม (ไม่บังคับ) | ระบบหาคู่แข่งจาก LLM และข่าว ให้คุณติ๊กยืนยัน แล้ววิเคราะห์แบบ Phase 2 |

### ใช้งาน

- **แถบซ้าย 3 ขั้น:** ① เทียบใครบ้าง ② สนใจเรื่องอะไร (หมวด/คำค้น ไม่บังคับ) ③ ข้อมูลจากไหน
  - ใส่หัวข้อที่สนใจ (เช่น 5G) ระบบจะค้นข่าว "ชื่อบริษัท + หัวข้อ" เพิ่ม แล้ววิเคราะห์เฉพาะรายการที่เกี่ยวกับหัวข้อนั้น (งบการเงินไม่เปลี่ยน)
  - สวิตช์ **ตัวเลือกละเอียด** เปิดการเลือกแหล่งข้อมูล จำนวนข่าว/รีวิว ดึงเนื้อหาเต็ม และปิดแหล่งเฉพาะบางบริษัทในการ์ดบริษัท
- **การ์ดแหล่งข้อมูลของแต่ละบริษัท:** บอกว่าแต่ละแหล่งใช้อะไร (ชื่อแอป ชื่อหุ้น เว็บ) แก้ได้จากปุ่ม "แก้ไข"
- **หน้าหลักแบ่งเป็นแท็บ:** ผลวิเคราะห์ · บริษัทและแหล่งข้อมูล (บริษัทในเครือ + การ์ดแหล่งข้อมูล) · ติดตามอัตโนมัติ · ข้อมูลภายใน
- **กล่อง "สิ่งที่ควรรู้"** บนสุดของผล: 3–5 ข้อสำคัญจากทุกส่วน (เรื่องสำคัญตั้งแต่รอบก่อน อันดับในหมวด หุ้นขยับหลังข่าว
  จุดที่ต่างจากคู่แข่งมากที่สุด) คิดโดยระบบ ไม่ใช่ LLM · หัวผลบอกจำนวนและเวลาที่ดึงล่าสุดของแต่ละแหล่ง
- **ดาวน์โหลดรายงานเป็น Word (.docx)** ลิงก์อ้างอิงกดได้ (ใช้ python-docx) หรือ Markdown
- **หน้าผลลัพธ์:** แถบตัวกรอง (บริษัท แหล่ง ช่วงเวลา หมวด น้ำเสียง คำค้น) กรองทุกกราฟ/ตารางทันที
  มีปุ่มเขียนรายงานใหม่ตามตัวกรอง (LLM 1 ครั้ง) · แท็บ สรุป / เรา vs คู่แข่ง / เจาะลึก (หมวดข่าว รีวิว งบ) / ข้อมูลทั้งหมด
  · ปุ่ม "คำศัพท์" อธิบาย gap จุด % YoY ROE ฯลฯ
- **บริษัทในเครือ:** สวิตช์ "รวมบริษัทในเครือ" (เปิดไว้) ใส่ชื่อบริษัทหรือเครือ เช่น CP, PTT, KTB
  ระบบหาบริษัทลูก/บริษัทร่วม (LLM 1 ครั้งรวมทุกชื่อ เก็บผลไว้ไม่ถามซ้ำ) แล้วตรวจผู้ถือหุ้นใหญ่ 10 อันดับแรกใน SET
  ติ๊กให้เองเฉพาะรายที่ยืนยันได้ (เช่น PTT → PTTEP, OR, GC) รายนอกตลาดตรวจไม่ได้ต้องติ๊กเอง
  บริษัทในเครือถูกวิเคราะห์แยกเป็นรายบริษัท แต่ไม่นับเป็นคู่แข่งในค่าเฉลี่ยคู่แข่ง/ตาราง gap (สูงสุด 20 บริษัทต่อรอบ)
- **ติดตามอัตโนมัติ** (หน้าหลัก หัวข้อ "ติดตามอัตโนมัติ"): บันทึกชุดบริษัทที่วิเคราะห์ไว้ แล้วกด "ตั้งเวลา"
  ให้ Windows Task Scheduler รัน `monitor.py` ทุกวัน (ต้องเปิดเครื่องไว้) หรือกด "รันตอนนี้" ให้รันเบื้องหลัง
  - ทุกรอบ (ทั้งรอบอัตโนมัติและรอบที่กดในแอป) ระบบเก็บตัวเลขของแต่ละบริษัทไว้ แล้วเทียบกับรอบก่อนว่าอะไรเปลี่ยน:
    แจ้งตลาดใหม่ งบใหม่ ข่าวลบใหม่ ข่าวสินค้า/โปรโมชันใหม่ % ข่าวลบ 30 วันเปลี่ยน ≥ 10 จุด ดาวรีวิวเปลี่ยน ≥ 0.3
    (คิดด้วย pandas ไม่ใช้ LLM) แสดงในกล่อง "อะไรเปลี่ยนไปตั้งแต่รอบก่อน" และเป็นหัวข้อแรกของรายงาน
  - แจ้งเตือนเข้าแชต: ใส่ `ALERT_WEBHOOK_URL` (Discord / Slack / Microsoft Teams / Google Chat) ใน `.env`
    ระบบส่งเฉพาะเมื่อมีเรื่องสำคัญ ทดสอบด้วย `python monitor.py --test-alert`
  - แท็บเจาะลึก → "แนวโน้ม": จำนวนข่าว % ข่าวลบ และดาวรีวิว รายสัปดาห์ (ยาวขึ้นเรื่อย ๆ เมื่อรันทุกวัน)
- **แหล่งอ้างอิงในรายงาน:** ข่าว งบ และสิ่งที่เปลี่ยนไปมีเลขอ้างอิง LLM ต้องใส่เลขท้ายประโยค
  ระบบแปลงเป็นลิงก์ `[1]` ไปยังข่าว/หน้างบใน SET และต่อท้ายรายการแหล่งอ้างอิงเฉพาะที่ถูกอ้างจริง
- **ข้อมูลภายในบริษัท** (หน้าหลัก): อัปโหลด CSV/Excel เช่น ยอดขาย NPS ส่วนแบ่งตลาด (มีไฟล์ตัวอย่างให้โหลด
  ใช้ "เรา" แทนชื่อบริษัทเราได้) ระบบเพิ่มในตาราง "เรา vs คู่แข่ง" แท็บเจาะลึก → "ข้อมูลภายใน" และในรายงาน
  ข้อมูลเก็บใน `data/app.db` เครื่องนี้ แต่ตัวเลขจะถูกส่งให้ LLM ตอนเขียนรายงาน ถ้าเป็นข้อมูลลับให้ปิด
  "ให้ LLM ใช้ข้อมูลภายในตอนเขียนรายงาน"
- **เทียบทั้งหมวด** (แท็บเจาะลึก, `core/benchmark.py`): เทียบกับทุกบริษัทจดทะเบียนในหมวดธุรกิจเดียวกันของ SET
  ไม่ใช่แค่คู่แข่งที่เลือก เช่น "อัตรากำไรสุทธิของ MC อันดับ 4 จาก 34 บริษัทในหมวดพาณิชย์" ใช้งบทั้งปีล่าสุด
  รายได้/กำไรโต อัตรากำไร ROE D/E มูลค่าตลาด P/E ปันผล (2 call ต่อหุ้น ไม่ใช้ LLM เก็บไว้ 1 วันในตาราง `market_cache`)
  หุ้นใน mai ที่ไม่มีหมวดใช้กลุ่มอุตสาหกรรมใน mai แทน · ปุ่ม "เพิ่มบริษัทในหมวดเดียวกับ …" ในแถบซ้าย
  เพิ่มบริษัทที่ใหญ่สุดตามมูลค่าตลาดในหมวดเดียวกันเข้าช่องคู่แข่ง · ตารางอันดับถูกส่งให้รายงานด้วย (Table S)
- **ราคาหุ้นหลังข่าว** (แท็บเจาะลึก, `core/impact.py`): วันที่มีข่าวหรือประกาศ SET หุ้นขยับเท่าไรใน 1 และ 3 วันทำการ
  เทียบราคาปิดก่อนข่าว "ผิดปกติ" = เกิน 2 เท่าของความผันผวนรายวันปกติของหุ้นตัวนั้น ข่าวหลัง 16:30 นับเป็นวันถัดไป
  หักผลของตลาดรวมแล้ว (ผลตอบแทนหุ้น − ดัชนี SET หรือ mai ช่วงเดียวกัน) เช่น MC −7.6% ใน 3 วัน ตลาด −0.8% หักแล้ว −6.7%
  กราฟราคา 6 เดือนพร้อมจุดข่าว · ทุกรอบที่พบการขยับผิดปกติใหม่จะเป็น "เรื่องสำคัญ" ในการติดตามอัตโนมัติ (ส่งแจ้งเตือน)
  ยังไม่หักวันขึ้นเครื่องหมาย XD
- **ถามข้อมูล** (แท็บ, `core/ask.py`): ถามเป็นภาษาไทย เช่น "AP เปิดโครงการใหม่อะไรบ้าง" ระบบตอบจากข้อมูลที่เก็บไว้เท่านั้น
  ทุกข้อมีลิงก์ที่มา ถ้าไม่มีข้อมูลจะตอบว่าไม่พบ (ไม่ใช้ความรู้ของ LLM) ใช้ LLM 2 ครั้งต่อคำถาม:
  แปลงคำถามเป็นตัวกรอง (บริษัท หมวด คำค้น ช่วงเวลา) → pandas คัดไม่เกิน 30 รายการ → เขียนคำตอบ
  คำถามเรื่องตัวเลขจะได้งบ อันดับในหมวด และราคาหุ้นหลังข่าวไปด้วย
- **ตรวจความแม่น** (แท็บ, `core/accuracy.py`): ผู้ตรวจกดทีละข่าวว่าเกี่ยวกับบริษัทไหม หมวดและน้ำเสียงถูกไหม
  (คิวสุ่ม ราว 1/3 เป็นข่าวที่ระบบตัดออก) ระบบแสดง % ข่าวที่เก็บไว้เกี่ยวจริง · % ข่าวที่ตัดออกไม่เกี่ยวจริง ·
  จับข่าวไม่เกี่ยวได้กี่ % (ประมาณตามสัดส่วนจริงในฐานข้อมูล) · หมวด/น้ำเสียงถูกกี่ % ใช้เป็นตัวเลขไปนำเสนอได้
  ข่าวที่ตรวจแล้ว (โดยเฉพาะที่ระบบเคยผิด) ถูกใส่เป็นตัวอย่างใน prompt จัดหมวดรอบถัดไป ระบบจึงตัดสินแบบที่องค์กรต้องการมากขึ้น
- หัวผลบอก "รอบนี้ใช้ LLM n ครั้ง (x วินาที)" นับจาก `llm_log`
- โค้ดหน้าเว็บแยกอยู่ใน `ui/` (labels, charts, insights, company_panel, company_picker, group_panel, internal_panel,
  watch_panel, results) ขั้นตอนวิเคราะห์อยู่ใน `core/pipeline.py` (ใช้ร่วมกันระหว่างแอปและ `monitor.py`)
  เทียบทั้งหมวดและราคาหุ้นดึงตอนวิเคราะห์เมื่อเปิดแหล่ง "งบการเงิน (SET)" หรือกดปุ่มดึงในแท็บนั้น

Phase 3 (`core/discover.py`) ใช้ LLM 3 ครั้งต่อการหา: ถามรายชื่อคู่แข่ง, ดึงชื่อจากหัวข้อข่าว, รวมชื่อซ้ำ
แล้วค้นข่าวที่พูดถึงคู่กันเพื่อเป็นหลักฐานและจัดอันดับ ถ้าไม่พบข่าวของบริษัทเราเลย ระบบจะบอกว่าหาไม่เจอแทนการเดารายชื่อ

## แหล่งข้อมูล

เลือกได้ที่แถบซ้าย หัวข้อ "แหล่งข้อมูล" ส่วนชื่อเรียก แอป และเว็บไซต์ของแต่ละบริษัท ตั้งค่าในหน้าหลัก
หัวข้อ "แหล่งข้อมูลของแต่ละบริษัท" (มีปุ่มหาอัตโนมัติ ตรวจก่อนกดบันทึก)

| แหล่ง | ได้อะไร | ข้อจำกัด |
|---|---|---|
| Google News | หัวข้อข่าวล่าสุดจากทุกสำนัก ค้นด้วยชื่อที่พิมพ์ + ชื่อที่สื่อใช้อีก 2 ชื่อ (เช่น AP → "เอพี (ไทยแลนด์)", "AP Thailand") | หัวข้ออย่างเดียว ช้ากว่าต้นทางได้หลายชั่วโมง |
| สำนักข่าวไทย (RSS) | ประชาชาติ, มติชน, ไทยรัฐ, Brand Inside, THE STANDARD, Blognone พร้อมเนื้อหา | มีแค่ 10–50 ข่าวล่าสุดของทั้งเว็บ จับบริษัทจากชื่อเรียก |
| รีวิวแอป | App Store + Google Play พร้อมดาว | ไม่ใช่ API ทางการ อาจพังได้ ต้องตั้งค่าแอปของแต่ละบริษัท |
| เว็บไซต์บริษัท | ลิงก์บทความจากหน้าข่าว/โปรโมชันที่ใส่ URL ไว้ | ใช้ได้กับเว็บที่ไม่ได้โหลดด้วย JavaScript และเคารพ robots.txt (เว็บค่ายมือถือส่วนใหญ่ใช้ไม่ได้) |
| ข่าวแจ้งตลาด SET | ประกาศที่บริษัทจดทะเบียนแจ้งตลาดฯ ย้อนหลัง 90 วัน (ประกาศงบ แต่งตั้งกรรมการ ซื้อกิจการ) ได้ภายในวันที่ประกาศ | เฉพาะบริษัทในตลาดหลักทรัพย์ฯ |
| งบการเงิน (SET) | งบรวมรอบล่าสุดเทียบช่วงเดียวกันปีก่อน งบรายปีย้อนหลัง ROE D/E มูลค่าตลาด P/E ปันผล ได้ตั้งแต่วันที่บริษัทยื่นงบ · ธนาคารเพิ่ม รายได้ดอกเบี้ยสุทธิ ค่าธรรมเนียม NIM (ประมาณ) cost to income credit cost สินเชื่อ/เงินฝาก | เฉพาะบริษัทในตลาด (NT ไม่มี) · ไม่มี NPL (งบย่อของ SET ไม่มี) |
| ดึงเนื้อหาเต็ม | เปิดลิงก์ข่าวแล้วอ่านเนื้อหา ให้ LLM สรุปจากเนื้อหา | ช้าลง ใช้ LLM มากขึ้น ทดสอบได้เนื้อหาเต็มราว 80% ของข่าว |

ช่องเลือกบริษัท (บริษัทของเรา / คู่แข่ง) แสดงบริษัทที่เคยวิเคราะห์ไว้บนสุด ตามด้วยหุ้นสามัญใน SET และ mai ทั้งหมด (ราว 930 ตัว ค้นได้ทั้งชื่อหุ้นและชื่อไทย เช่น "แม็ค" → MC)
บริษัทนอกตลาดพิมพ์ชื่อเองแล้วกด Enter · บริษัทที่เลือกจาก SET แสดงในผลด้วยชื่อหุ้น · ถ้าเว็บ SET ใช้ไม่ได้ ช่องเหลือเฉพาะบริษัทที่เคยวิเคราะห์

ข้อมูลบริษัทระบบหาให้เองตอนกดวิเคราะห์ครั้งแรก (LLM 1 ครั้งรวมทุกบริษัท): ชื่อหุ้น SET (ตรวจกับรายชื่อหุ้นจริง ถ้าพิมพ์ชื่อหุ้นมาเองจะใช้ชื่อตามทะเบียน SET) ชื่อที่สื่อใช้ และธุรกิจหลัก
ตอนจัดหมวด LLM ตรวจด้วยว่าข่าวเป็นเรื่องของบริษัทนั้นจริงไหม ข่าวที่ชื่อตรงแต่เป็นเรื่องอื่น (ซอย AP, พิธีกร MC, สำนักข่าว AP)
หรือแค่มีชื่ออยู่ในรายชื่อหุ้นเด่นประจำวัน จะถูกตัดออก (ไม่เรียก LLM เพิ่ม) ใช้ได้กับบริษัทนอกตลาดด้วย
ชื่อหุ้นหรือชื่อเรียกผิด แก้ได้ใน “แหล่งข้อมูลของแต่ละบริษัท” (ชื่อหุ้นเว้นว่าง = ไม่อยู่ในตลาด)

**ข้อมูลจาก SET** ใช้ API ภายในของเว็บ set.or.th ซึ่งไม่ได้เปิดให้ใช้อย่างเป็นทางการ อาจเปลี่ยนหรือถูกบล็อกได้
(ถ้าใช้ไม่ได้ แอปยังทำงานต่อและแจ้งเหตุผลในแถบสถานะ) ถ้าจะใช้งานจริงควรเปลี่ยนไปใช้ SETSMART ซึ่งเป็นบริการแบบเสียเงินของ SET
ตัวเลขงบคำนวณด้วย pandas (ตาราง F) แล้วส่งให้ LLM ใช้อ้างอิง และเพิ่มแถว "การเงิน" ในตาราง gap

ข้อมูลไม่ได้ real-time: ดึงใหม่ทุกครั้งที่กดวิเคราะห์ ข่าว/รีวิวที่เคยเก็บแล้วจะไม่ถูกส่งให้ LLM ซ้ำ
รีวิวแยกออกจากตารางหมวดข่าว (A/B/C) และมีตาราง R ของตัวเอง

- ข้อมูลดิบ: `data/raw/{company}/{date}.json`
- ฐานข้อมูล: `data/app.db` (ตั้ง `CC_DATA_DIR` เพื่อใช้โฟลเดอร์ข้อมูลอื่น เช่น ตอนทดสอบ)
- บันทึกการรันอัตโนมัติ: `data/monitor.log`
- กดซ้ำได้ ข่าวเดิมจะไม่ถูก classify ซ้ำ (ดูจำนวนครั้งที่เรียก LLM ที่แถบสถานะ)
