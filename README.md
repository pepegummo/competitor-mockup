## ติดตั้ง (Windows / PowerShell)

```powershell
cd competitor-mockup
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

สร้าง `.env` จาก `.env.example` (`copy .env.example .env`) แล้วใส่ key:

```
LLM_API_KEY=ใส่ key ของอาจารย์
```

### อ่าน PDF สแกน (OCR) — ไม่บังคับ

OCR รันใน container (มี Tesseract ภาษาไทยอยู่ใน image แล้ว ไม่ต้องลง Tesseract ในเครื่อง):

```powershell
docker build -t competitor-ocr ocr
docker run -d -p 8000:8000 --name ocr competitor-ocr   # ครั้งต่อไปใช้ docker start ocr
```

แล้วเพิ่มใน `.env`:

```
OCR_URL=http://localhost:8000
```

ไม่เปิด container ก็อัปโหลด PDF ได้ แต่อ่านได้เฉพาะ PDF ที่มีข้อความในไฟล์ หน้าสแกนจะขึ้นว่า "อ่านไม่ได้"
(ลง Tesseract + ภาษาไทยในเครื่องแล้วไม่ตั้ง `OCR_URL` ก็ OCR ได้เหมือนกัน)
ลองอัปโหลดด้วย `streamlit run app.py` ไม่ใช่ `run_demo.bat` เพราะโหมดเดโมใช้คำตอบ LLM ที่บันทึกไว้ เอกสารใหม่จึงสรุปไม่ได้

## รัน

```powershell
streamlit run app.py
```

เปิดครั้งแรกกดชุดตัวอย่าง (ค่ายมือถือ / ธนาคาร / อสังหา) ในหน้าภาพรวมได้เลย หรือไปเมนู "วิเคราะห์ใหม่" เพื่อตั้งค่าเอง
กด "เริ่มวิเคราะห์" แล้วระบบรันเบื้องหลัง (`monitor.py --job`) หน้าเว็บไม่ค้าง ความคืบหน้าแสดงในแถบซ้ายทุกหน้า
ระหว่างรอไปหน้าอื่นได้ เสร็จแล้วเปิดผลให้เอง (โหมดหาคู่แข่งยังรันในหน้าเว็บ เพราะต้องให้ติ๊กยืนยันรายชื่อ)

**โหมดเดโม (สำหรับนำเสนอ):** ดับเบิลคลิก `run_demo.bat` เปิดชุดข้อมูล MC vs AP, KCE, ฟู้ดแพชชั่น ที่เก็บไว้ใน `demo/`
ใช้ได้แม้ไม่มีเน็ตหรือเครื่อง LLM ล่ม: ผลวิเคราะห์ ตัวเลข SET ทั้งหมวด ราคาหุ้น และคำตอบของคำถามตัวอย่าง (ปุ่มในหน้าถามข้อมูล
+ "AP มีโครงการใหม่อะไรบ้าง", "Shopee ลดราคาเมื่อไหร่", "บาร์บีคิวพลาซ่ามีโปรอะไรล่าสุด") ถูกเก็บไว้แล้ว
- ทุกครั้งที่เรียก LLM ระบบบันทึก prompt และคำตอบในตาราง `llm_log` · `LLM_REPLAY=1` = คำถามที่เคยถามแล้วใช้คำตอบเดิม
  ไม่เรียกเครื่อง LLM · ถ้าเครื่อง LLM ล่ม ระบบลองใช้คำตอบเดิมของ prompt เดียวกันก่อนแจ้ง error
- คำถามใหม่ที่ไม่เคยถาม และการกดวิเคราะห์ใหม่ ยังต้องใช้เน็ต

เลือกรูปแบบในหน้า "วิเคราะห์ใหม่" ขั้น ①:

| โหมด | กรอก | ได้ผล |
|---|---|---|
| เทียบคู่แข่ง (Phase 1) | คู่แข่ง 2–5 ราย | ตาราง กราฟ และรายงานกลาง ๆ |
| เรา vs คู่แข่ง (Phase 2) | บริษัทเรา + คู่แข่ง 2–5 ราย | เพิ่มแท็บ gap (เรา − ค่าเฉลี่ยคู่แข่ง) และรายงานพร้อมข้อเสนอแนะ |
| หาคู่แข่งให้ (Phase 3) | บริษัทเรา + จำนวนคู่แข่ง (3–10) + อุตสาหกรรม (ไม่บังคับ) | ระบบหาคู่แข่งจาก LLM และข่าว ให้คุณติ๊กยืนยัน แล้ววิเคราะห์แบบ Phase 2 |

### ใช้งาน

- **เมนูด้านซ้าย:** ภาพรวม · วิเคราะห์ใหม่ · ถามข้อมูล | ติดตามอัตโนมัติ | ข้อมูลภายใน · บริษัทและแหล่งข้อมูล · ตรวจความแม่น
  ใต้เมนูบอกชุดที่เปิดอยู่ และความคืบหน้าเมื่อกำลังวิเคราะห์ (เห็นทุกหน้า)
- **วิเคราะห์ใหม่ 3 ขั้น:** ① เทียบใครบ้าง (บังคับ) ② สนใจเรื่องอะไร ③ ข้อมูลจากไหน (สองขั้นหลังพับไว้ ไม่บังคับ)
  - ใส่หัวข้อที่สนใจ (เช่น 5G) ระบบจะค้นข่าว "ชื่อบริษัท + หัวข้อ" เพิ่ม แล้ววิเคราะห์เฉพาะรายการที่เกี่ยวกับหัวข้อนั้น (งบการเงินไม่เปลี่ยน)
  - ขั้น ③ เลือกแหล่งข้อมูล จำนวนข่าว/รีวิว และดึงเนื้อหาเต็ม · กล่องท้ายหน้าบอกสิ่งที่ยังขาดก่อนกดเริ่ม
  - ค่าที่กรอกจำไว้ ไปหน้าอื่นแล้วกลับมาไม่หาย
- **บริษัทและแหล่งข้อมูล:** การ์ดของบริษัทที่จะวิเคราะห์ บอกว่าแต่ละแหล่งใช้อะไร (ชื่อแอป ชื่อหุ้น เว็บ) แก้ได้จากปุ่ม "แก้ไข"
  ติ๊กออกเพื่อไม่ใช้แหล่งนั้นกับบริษัทนั้น · บริษัทในเครือ · ดูแลข้อมูล
- **หน้าภาพรวม (ผลวิเคราะห์):** เรียงจากสรุปไปหารายละเอียด
  1. หัวผล: ชื่อชุด + จำนวนและเวลาที่ดึงล่าสุดของแต่ละแหล่ง + ปุ่ม **ตัวกรอง** · **ติดตาม** · **ดาวน์โหลด** · **วิเคราะห์ใหม่** · **คำศัพท์**
  2. **สิ่งที่ควรรู้** (3–5 ข้อสำคัญจากทุกส่วน คิดโดยระบบ ไม่ใช่ LLM) คู่กับ **อะไรเปลี่ยนไปตั้งแต่รอบก่อน**
  3. การ์ดสรุปของแต่ละบริษัท
  4. แท็บ สรุป (รายงาน) / เรา vs คู่แข่ง / เจาะลึก (หมวดข่าว รีวิว งบ) / ข้อมูลทั้งหมด
- **ตัวกรอง** (บริษัท แหล่ง ช่วงเวลา หมวด น้ำเสียง คำค้น) กรองทุกกราฟ/ตารางทันที กำลังกรองอยู่จะมีแถบบอกพร้อมปุ่มล้าง
  มีปุ่มเขียนรายงานใหม่ตามตัวกรอง (LLM 1 ครั้ง)
- **ดาวน์โหลด:** รายงาน Word (.docx ลิงก์อ้างอิงกดได้) · Markdown · ข้อมูลที่กรองแล้ว (.csv)
- **บริษัทในเครือ:** สวิตช์ "รวมบริษัทในเครือ" (เปิดไว้) ใส่ชื่อบริษัทหรือเครือ เช่น CP, PTT, KTB
  ระบบหาบริษัทลูก/บริษัทร่วม (LLM 1 ครั้งรวมทุกชื่อ เก็บผลไว้ไม่ถามซ้ำ) แล้วตรวจผู้ถือหุ้นใหญ่ 10 อันดับแรกใน SET
  ติ๊กให้เองเฉพาะรายที่ยืนยันได้ (เช่น PTT → PTTEP, OR, GC) รายนอกตลาดตรวจไม่ได้ต้องติ๊กเอง
  บริษัทในเครือถูกวิเคราะห์แยกเป็นรายบริษัท แต่ไม่นับเป็นคู่แข่งในค่าเฉลี่ยคู่แข่ง/ตาราง gap (สูงสุด 20 บริษัทต่อรอบ)
- **ติดตามอัตโนมัติ** (เมนู "ติดตามอัตโนมัติ" หรือปุ่ม "ติดตาม" บนหน้าผล): บันทึกชุดบริษัทที่วิเคราะห์ไว้ แล้วกด "ตั้งเวลา"
  ให้ Windows Task Scheduler รัน `monitor.py` ทุกวัน (ต้องเปิดเครื่องไว้) หรือกด "รันตอนนี้" ให้รันเบื้องหลัง
  (ใน docker ไม่ต้องตั้งในแอป: container `worker` รันทุกชุดทุกวันตาม `MONITOR_AT` ใน `.env`)
  - ทุกรอบ (ทั้งรอบอัตโนมัติและรอบที่กดในแอป) ระบบเก็บตัวเลขของแต่ละบริษัทไว้ แล้วเทียบกับรอบก่อนว่าอะไรเปลี่ยน:
    แจ้งตลาดใหม่ งบใหม่ ข่าวลบใหม่ ข่าวสินค้า/โปรโมชันใหม่ % ข่าวลบ 30 วันเปลี่ยน ≥ 10 จุด ดาวรีวิวเปลี่ยน ≥ 0.3
    (คิดด้วย pandas ไม่ใช้ LLM) แสดงในกล่อง "อะไรเปลี่ยนไปตั้งแต่รอบก่อน" และเป็นหัวข้อแรกของรายงาน
  - แจ้งเตือนเข้าแชต: ใส่ `ALERT_WEBHOOK_URL` (Discord / Slack / Microsoft Teams / Google Chat) ใน `.env`
    ระบบส่งเฉพาะเมื่อมีเรื่องสำคัญ ทดสอบด้วย `python monitor.py --test-alert`
  - แท็บเจาะลึก → "แนวโน้ม": จำนวนข่าว % ข่าวลบ และดาวรีวิว รายสัปดาห์ (ยาวขึ้นเรื่อย ๆ เมื่อรันทุกวัน)
- **แหล่งอ้างอิงในรายงาน:** ข่าว งบ และสิ่งที่เปลี่ยนไปมีเลขอ้างอิง LLM ต้องใส่เลขท้ายประโยค
  ระบบแปลงเป็นลิงก์ `[1]` ไปยังข่าว/หน้างบใน SET และต่อท้ายรายการแหล่งอ้างอิงเฉพาะที่ถูกอ้างจริง
- **ข้อมูลภายในบริษัท** (เมนู "ข้อมูลภายใน"): อัปโหลด CSV/Excel เช่น ยอดขาย NPS ส่วนแบ่งตลาด (มีไฟล์ตัวอย่างให้โหลด
  ใช้ "เรา" แทนชื่อบริษัทเราได้) ระบบเพิ่มในตาราง "เรา vs คู่แข่ง" แท็บเจาะลึก → "ข้อมูลภายใน" และในรายงาน
  ข้อมูลเก็บในฐานข้อมูลของระบบ (ไม่ออกนอกเครื่อง/บัญชีคลาวด์ของเรา) แต่ตัวเลขจะถูกส่งให้ LLM ตอนเขียนรายงาน ถ้าเป็นข้อมูลลับให้ปิด
  "ให้ LLM ใช้ข้อมูลภายในตอนเขียนรายงาน"
  - **เอกสาร PDF** (หน้าเดียวกัน ส่วนล่าง): เลือกว่าเป็นเอกสารของบริษัทไหน อ่านได้ครั้งละ 30 หน้า (ไฟล์ยาวกว่านี้เลือกช่วงหน้า
    แล้วอัปโหลดซ้ำเพื่ออ่านช่วงถัดไป) ระบบใช้ข้อความในไฟล์ก่อน หน้าสแกนหรือข้อความเพี้ยนใช้ OCR (`OCR_URL`)
    แล้วตัดเป็นส่วนละ ~1,500 ตัวอักษรให้ LLM สรุป (`core/internal.py` `save_pdf`, `core/ocr.py`)
    ใช้ในแท็บถามข้อมูลเท่านั้น ไม่นับในตาราง กราฟ รายงานเปรียบเทียบ หรือการแจ้งเตือน (มีแค่บางบริษัท ตัวเลขจะเพี้ยน)
    เนื้อหาถูกส่งให้ LLM · ลบรายไฟล์ได้ที่ "เอกสารที่บันทึกไว้"
- **เทียบทั้งหมวด** (แท็บเจาะลึก, `core/benchmark.py`): เทียบกับทุกบริษัทจดทะเบียนในหมวดธุรกิจเดียวกันของ SET
  ไม่ใช่แค่คู่แข่งที่เลือก เช่น "อัตรากำไรสุทธิของ MC อันดับ 4 จาก 34 บริษัทในหมวดพาณิชย์" ใช้งบทั้งปีล่าสุด
  รายได้/กำไรโต อัตรากำไร ROE D/E มูลค่าตลาด P/E ปันผล (2 call ต่อหุ้น ไม่ใช้ LLM เก็บไว้ 1 วันในตาราง `market_cache`)
  หุ้นใน mai ที่ไม่มีหมวดใช้กลุ่มอุตสาหกรรมใน mai แทน · ปุ่ม "เพิ่มบริษัทในหมวดเดียวกับ …" ในหน้าวิเคราะห์ใหม่
  เพิ่มบริษัทที่ใหญ่สุดตามมูลค่าตลาดในหมวดเดียวกันเข้าช่องคู่แข่ง · ตารางอันดับถูกส่งให้รายงานด้วย (Table S)
- **ราคาหุ้นหลังข่าว** (แท็บเจาะลึก, `core/impact.py`): วันที่มีข่าวหรือประกาศ SET หุ้นขยับเท่าไรใน 1 และ 3 วันทำการ
  เทียบราคาปิดก่อนข่าว "ผิดปกติ" = เกิน 2 เท่าของความผันผวนรายวันปกติของหุ้นตัวนั้น ข่าวหลัง 16:30 นับเป็นวันถัดไป
  หักผลของตลาดรวมแล้ว (ผลตอบแทนหุ้น − ดัชนี SET หรือ mai ช่วงเดียวกัน) เช่น MC −7.6% ใน 3 วัน ตลาด −0.8% หักแล้ว −6.7%
  กราฟราคา 6 เดือนพร้อมจุดข่าว · ทุกรอบที่พบการขยับผิดปกติใหม่จะเป็น "เรื่องสำคัญ" ในการติดตามอัตโนมัติ (ส่งแจ้งเตือน)
  ยังไม่หักวันขึ้นเครื่องหมาย XD
- **ถามข้อมูล** (เมนู "ถามข้อมูล" หรือลิงก์ท้ายรายงาน, `core/ask.py`): ถามเป็นภาษาไทย เช่น "AP เปิดโครงการใหม่อะไรบ้าง" ระบบตอบจากข้อมูลที่เก็บไว้เท่านั้น
  ทุกข้อมีลิงก์ที่มา ถ้าไม่มีข้อมูลจะตอบว่าไม่พบ (ไม่ใช้ความรู้ของ LLM) ใช้ LLM 2 ครั้งต่อคำถาม:
  แปลงคำถามเป็นตัวกรอง (บริษัท หมวด คำค้น ช่วงเวลา) → pandas คัดไม่เกิน 30 รายการ → เขียนคำตอบ
  คัดรายการด้วยคำค้น + ความหมาย (`core/embed.py`): ถาม "เน็ตบ้าน" เจอข่าว "บรอดแบนด์" แม้คำไม่ตรง ใช้โมเดล
  `multilingual-e5-small` รันในเครื่อง (ไม่นับเป็นการเรียก LLM ครั้งแรกโหลดโมเดล ~470MB และคำนวณเวกเตอร์ข่าว
  เก็บไว้ในตาราง `embeddings` ไม่คำนวณซ้ำ) ถ้าไม่ได้ลง `sentence-transformers` ใช้คำค้นอย่างเดียวเหมือนเดิม
  ตั้ง `EMBED_BACKEND=api` เมื่อ endpoint ของอาจารย์มีโมเดล embedding (ตอนนี้ key ใช้ได้แค่ qwen3.5)
  คำถามเรื่องตัวเลขจะได้งบ อันดับในหมวด และราคาหุ้นหลังข่าวไปด้วย
  ตอบจาก PDF ที่อัปโหลดได้ด้วย ที่มาแสดงเป็น "ชื่อไฟล์ · หน้า x" (ไม่มีลิงก์ เพราะไม่มีหน้าเว็บให้เปิด)
- **ตรวจความแม่น** (เมนู "ตรวจความแม่น", `core/accuracy.py`): ผู้ตรวจกดทีละข่าวว่าเกี่ยวกับบริษัทไหม หมวดและน้ำเสียงถูกไหม
  (คิวสุ่ม ราว 1/3 เป็นข่าวที่ระบบตัดออก) ระบบแสดง % ข่าวที่เก็บไว้เกี่ยวจริง · % ข่าวที่ตัดออกไม่เกี่ยวจริง ·
  จับข่าวไม่เกี่ยวได้กี่ % (ประมาณตามสัดส่วนจริงในฐานข้อมูล) · หมวด/น้ำเสียงถูกกี่ % ใช้เป็นตัวเลขไปนำเสนอได้
  ข่าวที่ตรวจแล้ว (โดยเฉพาะที่ระบบเคยผิด) ถูกใส่เป็นตัวอย่างใน prompt จัดหมวดรอบถัดไป ระบบจึงตัดสินแบบที่องค์กรต้องการมากขึ้น
- หัวผลบอก "รอบนี้ใช้ LLM n ครั้ง (x วินาที)" นับจาก `llm_log`
- **ดูแลข้อมูล** (หน้าบริษัทและแหล่งข้อมูล): รวมบริษัทที่ชื่อหุ้นเดียวกันแต่เป็นคนละแถว (เช่น True / True Corporation / ทรู)
  ย้ายข่าว งบ ข้อมูลภายในไปแถวที่เลือก ข่าวซ้ำถูกทิ้ง ชื่อเดิมกลายเป็นชื่อเรียก · จัดหมวดข่าวเก่าใหม่ (ตรวจความเกี่ยวข้องย้อนหลัง)
  ข่าวที่ตรวจด้วยมือแล้วไม่ถูกแตะ
- ดึงข้อมูล 3 บริษัทพร้อมกัน และส่ง LLM จัดหมวด 4 ชุดพร้อมกัน: AIS/True/NT ครบทุกแหล่งจาก 224 เหลือ 77 วินาที
- เทส: `pip install -r requirements-dev.txt` แล้ว `python -m pytest` (ไม่ใช้เน็ตหรือ LLM รวมเทสเปิดทุกหน้าเว็บกับชุดเดโม)
  · เทสกับ PostgreSQL (ฐานข้อมูลเทสถูกล้างทุกครั้ง ห้ามชี้ DB จริง):
  `docker run -d --name cc-pgtest -e POSTGRES_PASSWORD=test -p 55432:5432 pgvector/pgvector:pg16` แล้ว
  `$env:TEST_DATABASE_URL="postgresql://postgres:test@localhost:55432/postgres"; python -m pytest`
  เทส OCR ด้วย Tesseract ในเครื่องจะถูกข้าม (skipped) ถ้าไม่ได้ลง ซึ่งเป็นปกติ
- โค้ดหน้าเว็บอยู่ใน `ui/`: เมนู `ui/nav.py` · แต่ละหน้า `ui/pages/` · สถานะที่ใช้ร่วมกัน (ผลที่เปิดอยู่ ฟอร์ม
  งานเบื้องหลัง) `ui/state.py` · ส่วนประกอบ (results, panels, charts, sections) ขั้นตอนวิเคราะห์อยู่ใน `core/pipeline.py`
  (ใช้ร่วมกันระหว่างแอปและ `monitor.py`)
  เทียบทั้งหมวดและราคาหุ้นดึงตอนวิเคราะห์เมื่อเปิดแหล่ง "งบการเงิน (SET)" หรือกดปุ่มดึงในแท็บนั้น

Phase 3 (`core/discover.py`) ใช้ LLM 3 ครั้งต่อการหา: ถามรายชื่อคู่แข่ง, ดึงชื่อจากหัวข้อข่าว, รวมชื่อซ้ำ
แล้วค้นข่าวที่พูดถึงคู่กันเพื่อเป็นหลักฐานและจัดอันดับ ถ้าไม่พบข่าวของบริษัทเราเลย ระบบจะบอกว่าหาไม่เจอแทนการเดารายชื่อ

## รันด้วย Docker

ทั้งระบบรันด้วย `docker compose` ได้ทั้งบนเครื่องและบน ECS: `proxy` (Caddy: HTTPS + รหัสผ่านถ้าตั้ง) → `web` (Streamlit)
· `worker` (หยิบงานจากตาราง `jobs` + รันชุดติดตามทุกวันตาม `MONITOR_AT`) · `db` / `ocr` (เปิดด้วย profile)

ฐานข้อมูลเลือกด้วย `DATABASE_URL` ใน `.env` (รายละเอียดและการย้ายข้อมูลอยู่ใน [`DEPLOY.md`](DEPLOY.md)):
- RDS for PostgreSQL: ใส่ URL ของ RDS
- container `db` (PostgreSQL + pgvector): ใส่ `POSTGRES_PASSWORD` และ `DATABASE_URL=postgresql://app:<รหัส>@db:5432/competitor`
  แล้วเพิ่ม `--profile localdb` ทุกคำสั่ง · ย้ายข้อมูลเดิม: `docker compose exec worker python migrate_to_postgres.py /app/data/app.db`
- เว้นว่าง: SQLite ใน volume `app_data` (แบบเดิม ใช้ข้อ 4 ด้านล่างใส่ข้อมูลเดิม)

1. ใน `.env` เพิ่มค่าส่วน "docker compose เท่านั้น" จาก `.env.example`
   · บนเครื่อง Windows ใส่ `HTTP_PORT=8080` และ `HTTPS_PORT=8443` (Docker Desktop/WSL มักจองพอร์ต 443 ไว้ ไม่ใส่ proxy จะไม่ขึ้น)
   ค่าเริ่มไม่มีรหัสเข้าเว็บ · ถ้าจะตั้งรหัส:
   ```powershell
   docker run --rm caddy:2 caddy hash-password --plaintext 'รหัสผ่าน'
   ```
   ใส่ผลในเครื่องหมาย `'...'` เช่น `BASIC_AUTH_HASH='$2a$14$...'` (เว้นว่าง = ไม่มีรหัส ทุกคนเข้าได้)
2. รัน (ครั้งแรก build image นานหลายนาที มี torch และโมเดล e5 อยู่ในนั้น ใช้ดิสก์ราว 4.3 GB):
   ```powershell
   docker compose up -d --build                  # ไม่ใช้ OCR
   docker compose --profile ocr up -d --build    # ใช้ OCR: ใส่ OCR_URL=http://ocr:8000 ใน .env ด้วย
   ```
3. เปิด `http://localhost` (หรือ `:8080`) (ใส่ user/รหัสถ้าตั้ง `BASIC_AUTH_HASH`) · ดู log: `docker compose logs -f worker`
4. ใช้ข้อมูลเดิมในเครื่อง (ครั้งเดียว) ไฟล์ที่ `cp` เข้าไปเป็นของ root ต้อง `chown` ไม่งั้นแอปเขียน DB ไม่ได้:
   ```powershell
   docker compose cp data/app.db web:/app/data/app.db
   docker compose exec -u root web chown app:app /app/data/app.db
   docker compose restart web worker
   ```

ใน container ตั้ง `CC_JOB_QUEUE=1` ไว้ใน image: ปุ่ม "เริ่มวิเคราะห์" / "รันตอนนี้" แค่สร้างงานสถานะ `queued`
ให้ `worker.py` หยิบ (แทน `subprocess` + Windows Task Scheduler ที่ใช้ตอนรันบนเครื่อง ซึ่งยังทำงานเหมือนเดิม)

## แหล่งข้อมูล

เลือกได้ในหน้าวิเคราะห์ใหม่ ขั้น ③ ส่วนชื่อเรียก แอป และเว็บไซต์ของแต่ละบริษัท ตั้งค่าในหน้า "บริษัทและแหล่งข้อมูล"
(มีปุ่มหาอัตโนมัติ ตรวจก่อนกดบันทึก)

| แหล่ง | ได้อะไร | ข้อจำกัด |
|---|---|---|
| Google News | หัวข้อข่าวล่าสุดจากทุกสำนัก ค้นด้วยชื่อที่พิมพ์ + ชื่อที่สื่อใช้อีก 2 ชื่อ (เช่น AP → "เอพี (ไทยแลนด์)", "AP Thailand") | หัวข้ออย่างเดียว ช้ากว่าต้นทางได้หลายชั่วโมง |
| สำนักข่าวไทย (RSS) | ประชาชาติ, มติชน, ไทยรัฐ, Brand Inside, THE STANDARD, Blognone พร้อมเนื้อหา | มีแค่ 10–50 ข่าวล่าสุดของทั้งเว็บ จับบริษัทจากชื่อเรียก |
| รีวิวแอป | App Store + Google Play พร้อมดาว | ไม่ใช่ API ทางการ อาจพังได้ ต้องตั้งค่าแอปของแต่ละบริษัท |
| เว็บไซต์บริษัท | ลิงก์บทความจากหน้าข่าว/โปรโมชันที่ใส่ URL ไว้ | ใช้ได้กับเว็บที่ไม่ได้โหลดด้วย JavaScript และเคารพ robots.txt (เว็บค่ายมือถือส่วนใหญ่ใช้ไม่ได้) |
| ข่าวแจ้งตลาด SET | ประกาศที่บริษัทจดทะเบียนแจ้งตลาดฯ ย้อนหลัง 90 วัน (ประกาศงบ แต่งตั้งกรรมการ ซื้อกิจการ) ได้ภายในวันที่ประกาศ | เฉพาะบริษัทในตลาดหลักทรัพย์ฯ |
| งบการเงิน (SET) | งบรวมรอบล่าสุดเทียบช่วงเดียวกันปีก่อน งบรายปีย้อนหลัง ROE D/E มูลค่าตลาด P/E ปันผล ได้ตั้งแต่วันที่บริษัทยื่นงบ · ธนาคารเพิ่ม รายได้ดอกเบี้ยสุทธิ ค่าธรรมเนียม NIM (ประมาณ) cost to income credit cost สินเชื่อ/เงินฝาก | เฉพาะบริษัทในตลาด (NT ไม่มี) · ไม่มี NPL (งบย่อของ SET ไม่มี) |
| ดึงเนื้อหาเต็ม | เปิดลิงก์ข่าวแล้วอ่านเนื้อหา ให้ LLM สรุปจากเนื้อหา | ช้าลง ใช้ LLM มากขึ้น ทดสอบได้เนื้อหาเต็มราว 80% ของข่าว |

ช่องเลือกบริษัท (บริษัทของเรา / คู่แข่ง) แสดงบริษัทที่เคยวิเคราะห์ไว้บนสุด ตามด้วยหุ้นสามัญใน SET และ mai ทั้งหมด (ราว 930 ตัว ค้นได้ทั้งชื่อหุ้นและชื่อไทย เช่น "แม็ค" → MC)
บริษัทนอกตลาดพิมพ์ชื่อเองแล้วกด Enter · บริษัทที่เลือกจาก SET แสดงในผลด้วยชื่อหุ้น · ถ้าเว็บ SET ใช้ไม่ได้ ช่องเหลือเฉพาะบริษัทที่เคยวิเคราะห์

ข้อมูลบริษัทระบบหาให้เองตอนกดวิเคราะห์ครั้งแรก (LLM 1 ครั้งรวมทุกบริษัท): ชื่อหุ้น SET (ตรวจกับรายชื่อหุ้นจริง ถ้าพิมพ์ชื่อหุ้นมาเองจะใช้ชื่อตามทะเบียน SET) ชื่อที่สื่อใช้ และธุรกิจหลัก
ตอนจัดหมวด LLM ตรวจด้วยว่าข่าวเป็นเรื่องของบริษัทนั้นจริงไหม ข่าวที่ชื่อตรงแต่เป็นเรื่องอื่น (ซอย AP, พิธีกร MC, สำนักข่าว AP)
หรือแค่มีชื่ออยู่ในรายชื่อหุ้นเด่นประจำวัน จะถูกตัดออก (ไม่เรียก LLM เพิ่ม) ใช้ได้กับบริษัทนอกตลาดด้วย
ชื่อหุ้นหรือชื่อเรียกผิด แก้ได้ใน “แหล่งข้อมูลของแต่ละบริษัท” (ชื่อหุ้นเว้นว่าง = ไม่อยู่ในตลาด)

**ข้อมูลจาก SET** ใช้ API ภายในของเว็บ set.or.th ซึ่งไม่ได้เปิดให้ใช้อย่างเป็นทางการ อาจเปลี่ยนหรือถูกบล็อกได้
(ถ้าใช้ไม่ได้ แอปยังทำงานต่อและแจ้งเหตุผลในแถบสถานะ) ถ้าจะใช้งานจริงควรเปลี่ยนไปใช้ SETSMART ซึ่งเป็นบริการแบบเสียเงินของ SET
ตัวเลขงบคำนวณด้วย pandas (ตาราง F) แล้วส่งให้ LLM ใช้อ้างอิง และเพิ่มแถว "การเงิน" ในตาราง gap

ข้อมูลไม่ได้ real-time: ดึงใหม่ทุกครั้งที่กดวิเคราะห์ ข่าว/รีวิวที่เคยเก็บแล้วจะไม่ถูกส่งให้ LLM ซ้ำ
รีวิวแยกออกจากตารางหมวดข่าว (A/B/C) และมีตาราง R ของตัวเอง

- ข้อมูลดิบ: `data/raw/{company}/{date}.json`
- PDF ที่อัปโหลด (ไฟล์ต้นฉบับ): `data/uploads/<sha256>.pdf`
- ฐานข้อมูล: PostgreSQL ตาม `DATABASE_URL` · ไม่ตั้ง = `data/app.db` (ตั้ง `CC_DATA_DIR` เพื่อใช้โฟลเดอร์ข้อมูลอื่น เช่น ตอนทดสอบ)
- บันทึกการรันอัตโนมัติ: `data/monitor.log`
- กดซ้ำได้ ข่าวเดิมจะไม่ถูก classify ซ้ำ (ดูจำนวนครั้งที่เรียก LLM ที่แถบสถานะ)
